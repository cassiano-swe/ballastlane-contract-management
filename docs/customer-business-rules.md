# Customer creation business rules

`POST /api/customers` creates a customer. Text fields are trimmed before application validation and persistence.

- **Name:** required, not blank, at most 200 characters after trimming.
- **Customer type:** required; the only accepted JSON strings are `Individual` and `Company`. Numeric JSON values and numeric strings are rejected.
- **Trade name:** optional, at most 200 characters after trimming. It is allowed only for `Company`; an empty or whitespace-only value is treated as null.
- **Tax ID:** required, not blank, at most 50 characters after trimming. It is stored as a string, preserving leading zeros, punctuation, and case. It must be unique across customers. There is no country-specific tax ID validation or punctuation normalization.
- **Email:** required, not blank, valid format, at most 254 characters after trimming. It does not need to be unique.
- **ID:** generated by the application; it is not part of the request model.
- **Version:** generated by the application when creating a customer. The POST and GET responses expose the same persisted UUID while the customer remains unchanged. The POST request model has no version field.

For example, a request with `customerType: "Individual"` and a nonblank `tradeName` is invalid. The API responds with HTTP 400 and a `ValidationProblemDetails` whose `detail` explains that trade names are only allowed for companies; field errors are also available in `errors`. An invalid JSON value or missing field is reported in `detail` without including the submitted value. Duplicate tax IDs return 409; unexpected failures return 500 with generic details. Successful creation returns 201 and a `Location` header for the customer resource URL at `GET /api/customers/{id}`.

Customer creation is temporarily anonymous and is not intended for production until access is protected.
